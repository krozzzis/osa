# OSA agent guide

OSA is a reusable denix module library for NixOS and Home Manager. It is not
a machine configuration: identities, cosmetic presets, rice selection and
hosts belong in a composable downstream flake such as `~/osa-user`.

## Repository layout

- `flake-file.nix` is the source flake definition.
- `flake.nix` is generated by `github:vic/flake-file`; never edit it manually.
- `modules/osa/` contains all reusable modules, grouped by category.
- `modules/osa/user/` declares the public `user.*` interface.
- `check/` contains evaluation-only hosts that are invisible downstream.
- `lib/flake-inputs.nix` discovers module-local `inputs.nix` files.
- `packages/osa/` and `scripts/osa/` implement the `osa` command.

## Flake inputs

Declare a module-specific input in an `inputs.nix` beside the module:

```nix
_:
{
  flake-file.inputs.example = {
    url = "github:owner/project";
    inputs.nixpkgs.follows = "nixpkgs";
  };
}
```

After changing `flake-file.nix` or any `inputs.nix`, run `nix run .#write-flake`.
The `flake-file-in-sync` check rejects a stale generated `flake.nix`.

## Public `user.*` contract

OSA declares these options; downstream configurations only assign values.
Add every new `myconfig.user.*` dependency to
`modules/osa/user/default.nix` before consuming it. The username and email are
required. Other options cover profiles, typed application and font handles,
keyboard settings, UI dimensions, shortcuts, LSP servers and MCP servers.

Application handles require `.pkg` and accept an optional `.desktop`. Use
`lib.getExe app.pkg` when invoking one. Local MCP servers require a non-empty
command; remote servers require a non-empty URL.

## Module shape

```nix
{ delib, pkgs, ... }:
delib.module {
  name = "osa.category.name";
  options = { myconfig, ... }: {
    osa.category.name.enable = delib.boolOption myconfig.user.gui.enable;
    osa.category.name.pkg = delib.packageOption pkgs.package;
  };
  nixos.ifEnabled = { cfg, ... }: { };
  home.ifEnabled = { cfg, ... }: { };
  myconfig.ifEnabled = { ... }: { };
}
```

- Public options live under `myconfig.osa.<category>.<name>`.
- Use `delib.singleEnableOption false` when only an enable switch is needed.
- Lifecycles are `nixos`, `home` and `myconfig`, with `always`, `ifEnabled`
  and `ifDisabled` variants.
- Read other modules through `myconfig`; read the current module through `cfg`.
- Install `cfg.pkg`, never its default, so downstream overrides work.
- Development servers are opt-in and register in `user.dev.lsp` or
  `user.dev.mcp`.

## Mutable configuration and ownership

Codex and DMS write runtime state, so OSA keeps their files mutable, preserves
unmanaged keys and reconciles only OSA-owned keys. Do not move Codex back to
`programs.codex.settings`; that breaks runtime trust persistence.

`osa.de.dms` owns the package, inputs, greeter, compositor integration, power
behavior, plugins, wallpapers and mutable settings machinery. Downstream may
add cosmetic presets only. `osa.system.plymouth` consumes the packaged
`plymouth-theme-material` input; theme engine fixes belong upstream.

## Validation

```bash
nix flake check
nix run nixpkgs#deadnix -- --fail modules lib check flake-file.nix
git diff --check
```

Evaluate a real composed machine with local OSA changes:

```bash
cd ~/osa-user
nix eval .#nixosConfigurations.nixlaptop.config.system.build.toplevel.drvPath \
  --override-input osa ~/osa
```

## CLI and privileges

The default-enabled `osa.system.osa-cli` module installs `osa`. It uses
`~/osa-user` unless `--config` overrides the path. Run it as the normal user;
only `nixos-rebuild switch` and `boot` are elevated through systemd `run0`.

```bash
osa update
osa switch nixlaptop-niri
osa update-switch nixlaptop-niri
osa build-iso pi-backup
osa build-installer nixlaptop-niri
```
